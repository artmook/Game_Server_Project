# Game_Server_Project

.NET 10과 직접 TCP Socket을 사용하는 게임 서버 프로젝트입니다.
현재 `Server` 브랜치에는 A 담당 네트워크 기능을 구현했습니다.
방 생성·입장·퇴장·인원 제한 및 게임 로직은 포함하지 않습니다.

## 파일 구조와 변경 사항

```text
Game_Server_Project/
├── GameServerProject.slnx        Server, TestClient, NetworkTests 솔루션
├── README.md                    실행 방법, 통신 규격, B 담당 인계 내용
├── Server/
│   ├── Server.csproj            공통 소켓 소스를 연결해 컴파일
│   ├── Program.cs               7777 포트 실행, Ctrl+C 종료 요청, 실행 오류 출력
│   └── GameServer.cs            접속 목록, 메시지 처리, 대상별 전송, 종료 정리
├── TestClient/
│   ├── TestClient.csproj        공통 소켓 소스를 연결해 컴파일
│   └── Program.cs               독립적인 콘솔 입력·서버 수신, EXIT 종료
├── Shared/

└── Tests/
    ├── NetworkTests.csproj      외부 테스트 패키지 없는 콘솔 통신 테스트
    └── Program.cs               실제 TCP 연결 및 실제 TestClient 프로세스 검사
```

기존 C# 3개, 프로젝트 파일 2개, 솔루션, README를 수정했고 `Shared/`와 `Tests/`를 추가했습니다.
`bin/`, `obj/`, 테스트 실행 로그는 빌드 생성물이며 Git에서 제외됩니다.
공통 코드를 별도 라이브러리 프로젝트로 만들지 않고 두 프로젝트에서 같은 소스 파일을 링크했습니다.
두 프로그램의 송수신 규격이 달라지는 문제를 방지하면서 프로젝트 구성을 단순하게 유지하기 위한 선택입니다.

## 실행 방법

Windows 터미널의 PowerShell에서 실행합니다. .NET 10 SDK가 필요합니다.

```powershell
cd D:\GS_Project\Game_Server_Project
dotnet build
dotnet run --project Server --no-build
```

서버를 실행한 채로 터미널 탭을 3~4개 더 열고 각 탭에서 실행합니다.

```powershell
cd D:\GS_Project\Game_Server_Project
dotnet run --project TestClient --no-build
```

클라이언트마다 `SERVER|CONNECTED|1` 같은 ID 안내를 받습니다.
각 클라이언트에서 다음 명령을 입력합니다.

```text
HELLO
안녕하세요
BROADCAST|다른 클라이언트도 이 메시지가 보이나요?
EXIT
```

- `HELLO` → 보낸 클라이언트에게 `SERVER|RECEIVED|HELLO`.
- 일반 문자열 → 보낸 클라이언트에게 `SERVER|RECEIVED|{문자열}`.
- `BROADCAST|내용` → 송신자를 포함한 현재 접속자에게 `SERVER|BROADCAST|{송신자ID}|{내용}`.
- `EXIT` → TestClient의 로컬 종료 명령으로, 서버에 전송하지 않습니다. 대소문자를 구분하지 않습니다.
- TestClient는 입력 대기 중에도 방송을 받습니다. 출력이 입력 중인 줄 사이에 나타날 수 있습니다.
- 클라이언트의 `EXIT` 또는 Ctrl+C는 연결을 정리합니다. 서버의 Ctrl+C는 전체 연결과 처리 작업을 정리합니다.

## 통신 규격과 제한

한 메시지는 `UTF-8 문자열 + LF(0x0A)`입니다. LF는 공통 전송 코드가 자동으로 붙입니다.
`SendAsync`에 넘기는 문자열에는 끝의 LF를 넣지 않습니다.

| 항목 | 규칙 |
|---|---|
| 서버 주소 | 모든 IPv4 인터페이스의 7777 포트 |
| TestClient 접속 주소 | 127.0.0.1:7777 |
| 인코딩 | BOM 없는 UTF-8, 잘못된 UTF-8은 오류 처리 |
| 메시지 경계 | LF 한 바이트. CRLF는 지원하지 않음 |
| 본문 내 줄바꿈 | CR과 LF 모두 금지 |
| 클라이언트 입력 최대 | UTF-8 4,096바이트. `BROADCAST\|` 같은 명령 접두사도 포함하며 마지막 LF는 제외 |
| 공통 메시지 최대 | UTF-8 8,192바이트. 마지막 LF는 제외하므로 실제 전송은 최대 8,193바이트 |
| 동시 접속 제한 | 100개. ID 안내를 보내는 중인 연결도 포함 |
| 송신 제한시간 | 한 번의 SendAsync에 10초. 같은 소켓의 송신 대기 시간도 포함 |
| 접속 제한시간 | TestClient의 서버 접속 시도에 10초 |

한글은 보통 한 글자가 UTF-8 3바이트이며 이모지는 더 클 수 있으므로 글자 수와 바이트 수는 다릅니다.
서버가 응답에 명령 접두사와 ID를 붙일 수 있도록 클라이언트 입력은 공통 메시지 제한보다 작게 정했습니다.
비정상 UTF-8, 크기 초과, CR, LF 없이 중간에 종료된 메시지는 기록한 뒤 해당 연결을 종료합니다.
TestClient는 4,096바이트 초과 입력을 전송 전에 거부하고 다음 입력을 받습니다.
빈 LF 메시지는 서버에서 빈 문자열로 취급하지만 TestClient는 빈 입력과 공백 입력을 전송하지 않습니다.

기존 HELLO의 응답 내용은 유지하지만, 이전처럼 LF 없이 문자열만 보내는 클라이언트는 새 규격에 맞게 수정해야 합니다.

## 핵심 구현과 설명할 수 있어야 할 코드

### Shared/TcpConnection.cs

- `ReceiveAsync`: 수신 버퍼의 남은 바이트를 보존하면서 LF까지 메시지 버퍼에 모읍니다.
  TCP의 한 번 수신은 한 메시지라는 보장이 없기 때문에 경계를 직접 처리합니다.
  여러 메시지가 합쳐져 와도 다음 호출에서 남은 데이터를 읽습니다.
  전체 메시지를 모은 뒤 UTF-8로 해석하므로 한글·이모지의 중간 바이트에서 수신이 나뉘어도 복원됩니다.
- 고정 크기 버퍼와 크기 검사: LF 없이 계속 보내도 메시지 버퍼가 무제한 커지지 않습니다.
- `SendAsync`의 전송 반복문: Socket.SendAsync가 반환한 실제 바이트 수만큼 이동하고 남은 부분을 계속 보냅니다.
- `SemaphoreSlim`: 같은 소켓으로 여러 방송·개인 응답이 겹쳐도 메시지 전체를 하나씩 전송합니다.
  잠금 범위는 각 메시지의 마지막 LF까지이며, 다른 소켓의 전송은 막지 않습니다.
- 송신 실패 시 연결 종료: 메시지 일부만 전송된 연결을 그대로 재사용하면 다음 메시지와 합쳐질 수 있습니다.
- `sendStateLock`과 `activeSends`: 닫는 중에 새 송신이 등록되지 않게 하고, 마지막 송신 작업이 끝난 뒤
  SemaphoreSlim을 정리합니다. 대기 중인 송신에 잠금을 갑자기 Dispose하는 경합을 방지합니다.
- 수신은 연결당 한 작업만 호출해야 합니다. 송신은 여러 작업이 호출해도 됩니다.

### Server/GameServer.cs

- `StartAsync`: 접속 수락과 클라이언트별 작업 추적을 담당합니다.
  `Task.Yield`로 클라이언트 작업을 먼저 분리하여, 메시지가 이미 도착한 경우에도 접속 수락이 계속 진행됩니다.
- ID 안내 후 목록 등록: 새 연결이 방송보다 먼저 자신의 ID를 받도록 순서를 보장합니다.
- `ConcurrentDictionary`: 여러 수신·송신·종료 작업이 동시에 접속 목록을 조회하고 변경할 수 있습니다.
- `SendToClientAsync`: 한 ID로 전송합니다. 이미 사라진 ID나 통신 실패는 false이며 통신 오류는 기록합니다.
- `SendToClientsAsync`: ID 목록의 중복을 제거하고 대상별로 병렬 전송합니다. 느린 대상 때문에 다른 대상의 전송 시작이 막히지 않습니다.
- `HandleClientAsync`: 기본 명령 처리와 연결별 오류 경계입니다. 오류를 기록하고 해당 연결만 정리합니다.
- 종료 처리: 전체 취소를 알리고 소켓을 닫은 뒤 추적 중인 클라이언트 작업을 모두 기다립니다.
  접속 목록 제거와 종료 이벤트도 작업의 finally에서 실행됩니다.

### TestClient/Program.cs와 Server/Program.cs

- TestClient는 수신 작업을 계속 실행하면서 콘솔 입력을 별도로 기다립니다.
  `Task.WhenAny`로 입력과 수신 종료를 함께 관찰하므로, 입력 중에 서버가 끊겨도 종료할 수 있습니다.
- Windows 콘솔의 동기 ReadLine은 즉시 취소되지 않을 수 있어 입력 대기를 ThreadPool 작업으로 옮겼습니다.
  종료 시 남은 입력 대기는 프로세스의 백그라운드 스레드와 함께 끝나며, 다음 입력 작업을 추가하지 않습니다.
- 두 프로그램 모두 Ctrl+C의 즉시 프로세스 종료를 취소하고 CancellationToken으로 정리 경로를 실행합니다.
- 시작/통신 오류는 출력하며 프로그램 오류 시 종료 코드 1을 반환합니다.

## B 담당자 인계

방 관리 클래스는 별도로 작성하고, 서버 실행 전에 처리 지점을 연결합니다.
현재 코드에는 방 생성, 입장, 퇴장, 최대 4명 제한을 구현하지 않았습니다.

| 공개 API | 사용 목적 |
|---|---|
| `ClientIds` | 현재 안내가 완료된 접속자의 ID 스냅샷 |
| `SendToClientAsync(id, message, token)` | 특정 접속자에게 응답. Task<bool> 반환 |
| `SendToClientsAsync(ids, message, token)` | 같은 방 등의 ID 목록에 전송. Task 반환 |
| `MessageHandler` | `Func<int, string, CancellationToken, Task>` 형식의 추가 명령 처리 |
| `ClientDisconnected` | `Action<int>` 형식의 접속 종료 알림. 방에서 해당 ID를 제거할 위치 |

- `MessageHandler`를 설정하지 않으면 일반 문자열 확인 응답을 사용합니다.
  설정하면 HELLO와 BROADCAST 이외의 메시지는 이 처리기로 전달합니다. 처리기를 실행 중 바꾸지 말고 시작 전에 연결하세요.
- HELLO와 BROADCAST는 A의 테스트 명령으로 예약되어 있습니다.
- 방별 방송은 `SendToClientsAsync(방의 ID 목록, 메시지, token)`을 사용하세요.
  B 기능 추가 후 테스트용 전체 BROADCAST의 유지 여부는 팀에서 정하면 됩니다.
- ID는 같은 GameServer 인스턴스에서 재접속 시 새로 부여합니다. 영속적인 계정 ID가 아닙니다.
- 다른 클라이언트의 MessageHandler는 동시에 실행될 수 있습니다. 방 목록 변경과 수신자 스냅샷 생성에 동시성 처리가 필요합니다.
- 연결 종료 알림도 다른 클라이언트의 명령 처리와 겹칠 수 있습니다. 중복 퇴장에 안전하게 작성하세요.
- 방 잠금을 잡은 채 네트워크 송신을 기다리지 말고, 잠금 안에서 수신자 ID 목록을 복사한 다음 전송하세요.
- 처리기 내부에서도 전달된 취소 토큰을 사용하세요. B 처리기가 취소를 무시하고 무한 대기하면 서버 종료 대기도 끝나지 않습니다.
- 그룹 송신은 대상별 실패를 기록·정리하고 나머지 전송을 계속합니다. 개별 성공 여부가 필요하면 개인 전송의 bool을 확인하세요.

## 남은 제한과 미검증 범위

- TCP에는 메시지 경계가 없으므로 다른 클라이언트도 반드시 같은 LF 규격을 사용해야 합니다. 여러 줄 본문은 지원하지 않습니다.
- 정상 종료는 연결과 작업의 정리를 보장하는 방식이며, 종료 직전 진행 중이던 메시지의 전달 완료까지 보장하지는 않습니다.
